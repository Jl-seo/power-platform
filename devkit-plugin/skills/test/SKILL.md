# test — 자동 검증 + 헬스 카드

## 흐름

1. 설계도(IR)와 권한 표를 읽는다.
2. 자동 케이스 생성:
   - **데이터**: 필수 필드 누락, PII 누설, 권한 없는 사용자가 쓰려고 시도 등
   - **화면**: 빈 상태(데이터 0건), 입력 검증, 모바일 너비
   - **워크플로우**: 트리거 조건 충족·미충족, 외부 시스템 실패 시 재시도
3. 실행은 격리된 임시 환경에서 — 실제 데이터/시스템에 영향 X.
4. 결과를 *"전부 통과 / 1~3개 살펴보기"* 형식 헬스 카드로.
5. 골든셋(`goldens/<id>.ir.json`)이 있으면 회귀 비교 추가.

## 사용자 화면 용어 정책

`${CLAUDE_PLUGIN_ROOT}/references/glossary.md`. *unit / integration / e2e / coverage / golden* 같은 단어 노출 금지. *자동 검증 / 어디까지 봤는지 / 기준 비교* 정도.

## 출력 메시지 (사용자에게 보여줄 말)

```
🩺 헬스 카드

🟢 전부 통과예요 (검증 N개)

또는

🟡 살펴볼 것 N개:
  • 주문 입력 화면이 모바일에서 잘려요. 자동으로 한 줄 형식으로 바꿔볼까요?
  • 재고 0일 때 빈 화면 안내 문구가 없어요. 추가할까요?

⚪ 안 본 곳: <검증 못 한 영역, 있을 때만>
```

## 안 좋은 패턴 (회피)

- "테스트 작성하세요"라고 사용자에게 강요 X — 도구가 자동.
- 실패 케이스 raw 로그를 사용자에게 노출 X — 한 줄 자연어로.
