# zoom-out — 큰 결정 직전 한발 물러나기

## 자동 발동 조건

다음 중 하나라도 충족되면:
- IR 패치 크기가 IR 노드 수의 30% 이상
- 새 외부 시스템 연결 추가(SMS·이메일·외부 API·Teams 등)
- 환경이 *실서비스/외부* 로 격상되는 작업
- 비가역 작업(컬럼 삭제·표 삭제·환경 삭제)
- 사용자 의도가 너무 단편적이라 다음 단계 추론이 모호함

## 흐름

1. 현재 IR과 변경 의도를 한 줄씩 짧게 요약.
2. 다음 카드를 사용자에게:

```
잠시만요 — 이 작업이 큰 그림에서 이런 위치예요.

지금 만드는 것: <한 줄>
이번 변경: <한 줄>
영향: <한 줄, 예: "주문 화면 1, 표 2, 자동화 1">

이대로 갈까요, 아니면 한 번 더 정리하고 갈까요?
  [그대로 / 정리하고 / 그만두기]
```

3. *정리하고* 선택 시 → `clarify` 깊이 모드로 진입(3라운드 캡 해제).
4. *그만두기* 선택 시 → 변경 폐기, IR 원상복구.
5. *그대로* 선택 시 → 원래 흐름 계속.

## 사용자 화면 용어 정책

`${CLAUDE_PLUGIN_ROOT}/references/glossary.md`. *zoom out / scope / blast radius* 같은 영어 표현 노출 금지. *큰 그림 / 영향 범위 / 한발 물러서기* 같이.

## 안 좋은 패턴 (회피)

- 모든 변경에 zoom-out 호출 — 피로. 위 자동 발동 조건만.
- *"확인 차"* 의미 없는 yes/no — 항상 변경의 *영향*을 한 줄로 보여줘야.
- 사용자가 *"그대로"*를 골랐는데 또 묻기.
