# multi-review — 세 페르소나 종합 리뷰

## 흐름

1. 현재 IR 읽기. critic 점수 결과 있으면 함께 컨텍스트로 사용.
2. **세 페르소나 호출** — 다음 순서:
   - `review-pm` (기획)
   - `review-designer` (디자인)
   - `review-ux` (사용성)
   각 페르소나는 독립적으로 의견을 만든다(서로 영향 X).
3. **종합 카드 작성** — 세 의견을 한 화면에 묶고, *공통 우려 / 페르소나별 우려*로 정리.
4. **부분 수락 흐름** — 사용자가 어느 의견부터 반영할지 고르면 `refine` 스킬을 호출해 부분 패치 적용.

## 자동 발동 조건

다음 중 하나라도 충족되면 자동:
- critic의 `overall` < 0.7
- critic의 `findings`에 high 3개 이상
- IR diff가 IR 노드 수의 30% 이상
- 사용자가 *"리뷰 / 출시 전 점검 / 다관점"* 류 단어 사용

## 사용자 화면 용어 정책

`${CLAUDE_PLUGIN_ROOT}/references/glossary.md`. 사용자에게 *페르소나 / 종합 점수 / 회귀* 같은 단어 노출 금지.

## 종합 출력 (사용자에게 보여줄 말)

```
세 사람 의견을 모아봤어요 🧑‍💼🎨🧭

공통으로 짚힌 한 가지:
  • <세 페르소나가 모두 짚은 항목 한 줄>

기획자: <한 줄 핵심>
디자이너: <한 줄 핵심>
UX: <한 줄 핵심>

먼저 반영할 거 골라주세요:
  ① <…>
  ② <…>
  ③ 다 안 고치고 진행
```

번호 누르면 `refine` 호출 → 부분 변경 → `eval`로 다시 점검 → 사용자에게 결과 한 줄.

## 안 좋은 패턴 (회피)

- 세 페르소나 의견 6+개를 모두 나열(피로). *공통 1개 + 각자 1개*만.
- 세 의견이 충돌할 때 *"어느 게 옳다"* 단정 X — 사용자가 고르도록.
- 대답 없는 일방향 종합 발표 X — 항상 *"먼저 반영할 거 골라주세요"*로 끝낸다.
