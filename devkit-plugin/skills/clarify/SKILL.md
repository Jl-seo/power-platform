# clarify — 자연스러운 역질문 인터뷰어

## 사용자 화면 용어 정책

`${CLAUDE_PLUGIN_ROOT}/references/glossary.md` 의 표를 따라 **모르는 사람도 쉽게** 알아들을 수 있게 말한다. ADR/RBAC/IR 같은 약어는 사용자에게 노출 금지.

## 사용 원칙

1. **한 번에 1~3개**의 명확한 질문만. 4개 넘으면 사용자가 피곤해함.
2. 각 질문의 첫 번째 옵션은 **추천값**(라벨 끝 `(Recommended)`). 답을 모를 때 누르면 합리적인 기본값으로 진행.
3. 마지막 옵션은 항상 *"잘 모르겠어요"* — 도구가 알아서 정해 진행.
4. 이미 결정된 것은 다시 묻지 않는다(설계도의 *결정 기록* 섹션 참고).
5. 한 작업에서 기본 3번까지만 묻고, 그 후엔 기본값으로 진행 + *"마음에 안 드시면 알려주세요"* 안내.
   - **깊이 모드(grill)**: zoom-out이나 multi-review가 *"한 번 더 정리"* 결과로 진입을 요청하면 3라운드 cap을 해제하고 결정 트리가 다 풀릴 때까지 묻는다(Matt Pocock의 grill-me 패턴 차용). 이 경우 매 라운드 시작 전에 *"몇 가지 더 짚고 갈게요"* 한 줄 안내.
6. 답을 받으면 *결정 기록(ADR)* 항목으로 한 줄 추가하기 — 내부 처리는 IR의 `spec.adr` 배열에 JSON Patch로 추가하지만, 사용자에겐 *"이렇게 정한 이유를 적어두었어요"* 정도로만 알린다.

## 좋은 질문 만드는 법

- **모호한 부분만**: 사용자가 이미 명시한 것은 묻지 않는다.
- **결정 가능한 형태**: "어떻게 생각하세요?" X. "A vs B vs 잘 모름" O.
- **구체적**: "사용자 경험 중요?" X. "삭제 후 휴지통(30일 보관) vs 즉시 영구삭제 vs 잘 모름" O.
- **trade-off 명시**: 옵션 description에 한 줄 trade-off 적기.

## 안 좋은 패턴 (회피)

- 한 라운드에 5개 이상 질문 (피로)
- default 없는 open-ended 질문
- 이미 답한 영역 재질문
- "확인 차" 의미 없는 yes/no
- 질문 던지고 사용자 답 기다리지 않고 자기가 결정해버리기

## 출력 (사용자에게 보여줄 말)

질문이 끝나면 다음 한 카드:

```
✅ 정해진 것 N개:
   • <한 줄>
   • <한 줄>

다음에는 <자연어, 예: "데이터 표를 만들어 볼게요"> 진행할게요.
```

**나쁜 예**: *"3 round complete. ADR 3건 추가. 다음 스킬 data 호출 예정."*
**좋은 예**: *"세 가지 정해두었어요. 다음에는 데이터 표를 그려볼게요."*
