바이브코딩 플랫폼 구조안

기반 방식: GitHub Copilot 코딩 에이전트 + GitHub Actions + Azure Container Apps 작성일: 2026.09.01 상태: 초안 (검토용)

핵심 결론

  • 코드 작성은 GitHub Copilot 코딩 에이전트, 빌드와 배포는 GitHub Actions에 위임 — 자체 개발 범위는 요청 접수 화면과 연결 계층으로 한정함
  • 실행 환경은 미리보기(초경량, 미사용 시 0으로 축소)와 운영(정식 자원)으로 이원화 — 사용성은 유지하고 비용은 사용 시간 기준으로만 발생하도록 함
  • 모든 코드가 GitHub 저장소에 남고 검토 단계를 강제할 수 있어, "안전한 바이브코딩" 통제 요건을 별도 장치 없이 충족함
  • 어설픈 구현은 사용자 이탈로 직결되므로, 미리보기 반응 속도를 최우선 품질 기준으로 설정함

전체 흐름 — 요청부터 배포까지

Microsoft·GitHub 제공 자체 개발 설정·조합 (코드 소량) 단계를 누르면 상세 내용 표시
1단계
요청 접수 화면
자연어로 만들고 싶은 앱 설명 입력, 진행 상태와 결과 확인
2단계
요청 변환
사용자 요청을 작업 지시서 형태의 GitHub 이슈로 생성
3단계
코드 작성
Copilot 코딩 에이전트가 브랜치 생성, 코드 작성, Pull Request 등록
4단계
자동 검사
빌드, 비밀정보 탐지, 취약점 검사, 금지 라이브러리 차단
5단계
미리보기 게시
브랜치별 임시 환경에 자동 배포, 사용자에게 주소 전달
6단계
수정 반복
사용자 피드백을 같은 이슈에 추가, 에이전트가 재작업
7단계
승인·운영 배포
검토자 승인 후 병합, 운영 환경으로 배포, 미리보기 환경 정리
단계를 선택하면 담당 구성요소, 구축 방식, 유의점을 표시함

진행 단계안

1단계 (4~6주)
동작 검증
  • 저장소 1개, 화면 없이 이슈 직접 작성
  • 에이전트 코드 작성부터 미리보기 게시까지 자동 연결
  • 소요 시간과 결과 품질 측정
권고: 여기서 계속 진행 여부 판단
2단계 (6~8주)
사용자 화면·통제
  • 요청 접수 화면과 연결 계층 개발
  • 수정 반복, 승인 게이트, 수명 정책 적용
  • 내부 사용자 10명 시범 사용
3단계 (4주)
운영 전환
  • 운영 배포 경로와 비용 보고 완성
  • 사내 데이터 연결 허용 목록 운영
  • 사용자 안내 자료 배포
판단 기준 — 1단계에서 요청 후 미리보기까지 10분 이내, 단순 웹 앱 기준 첫 시도 성공률 70% 이상 확보 시 진행. 미달 시 자체 구축 대신 기존 서비스의 통제 사용(안전한 바이브코딩 플랫폼 안)으로 전환 검토
